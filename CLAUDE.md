# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ACE (Adaptive Communication Environment, `ACE/`) is a portable C++ framework for networked/concurrent
applications. TAO (`TAO/`) is a CORBA ORB built on ACE. Minimum language level is C++17 (CI also builds with
`c++std=c++20`/`c++23`). Upstream is https://github.com/DOCGroup/ACE_TAO.

## Build setup

There are no checked-in Makefiles or CMakeLists. Build files are generated by **MPC** (MakeProjectCreator, a
separate repo: https://github.com/DOCGroup/MPC) from `*.mpc` / `*.mwc` / `*.mpb` files. Required environment:

```bash
export ACE_ROOT=$PWD/ACE TAO_ROOT=$PWD/TAO MPC_ROOT=/path/to/MPC   # clone DOCGroup/MPC
export DYLD_LIBRARY_PATH=$ACE_ROOT/lib:$DYLD_LIBRARY_PATH           # LD_LIBRARY_PATH on Linux
export PATH=$ACE_ROOT/bin:$PATH
```

One-time per-checkout config files (all gitignored), as done in `.github/workflows/macosx.yml`:

```bash
echo '#include "ace/config-macosx.h"' > $ACE_ROOT/ace/config.h                    # config-linux.h on Linux
echo 'include $(ACE_ROOT)/include/makeinclude/platform_macosx.GNU' \
  > $ACE_ROOT/include/makeinclude/platform_macros.GNU                              # platform_linux[_clang].GNU
printf 'ipv6=1\nversioned_namespace=1\n' > $ACE_ROOT/bin/MakeProjectCreator/config/default.features
```

Optional build variants are set both as MPC features (`default.features`) and make macros
(`platform_macros.GNU`), e.g. `c++std=c++20`, `corba_e_micro=1`, `corba_e_compact=1`, `ace_for_tao=1`,
`uses_wchar=1`, `inline=0`.

Generate and build (GNU make):

```bash
perl $ACE_ROOT/bin/mwc.pl -type gnuace $TAO_ROOT/TAO_ACE.mwc -workers 4   # ACE core + TAO + TAO_IDL + orbsvcs
make -j8 -C $TAO_ROOT

perl $ACE_ROOT/bin/mwc.pl -type gnuace $ACE_ROOT/tests/tests.mwc          # ACE unit tests
make -j8 -C $ACE_ROOT/tests
```

To build one directory (e.g. a single TAO test), run `mwc.pl -type gnuace` in/on that directory and then `make`
there. After adding or editing an `.mpc` file, re-run `mwc.pl` before building. `-type cmake` is also supported
(see `.github/workflows/cmake.yml`); `vs2022` etc. for Windows.

## Running tests

Tests are Perl-driven and need `ACE_ROOT`/`TAO_ROOT` set and the binaries already built.

- Single ACE unit test: `cd $ACE_ROOT/tests && perl run_test.pl -t Thread_Pool_Test` (logs land in `log/`).
  Without `-t` it runs everything in `ACE/tests/run_test.lst` that matches the active configs.
- Single TAO test: `cd $TAO_ROOT/tests/Hello && perl run_test.pl` (most accept `-debug`).
- Test suites: `perl $ACE_ROOT/bin/auto_run_tests.pl -a` (ACE), `-o` (TAO ORB), `-t` (other TAO); `-z` dry-run.

Test lists (`ACE/bin/ace_tests.lst`, `TAO/bin/tao_orb_tests.lst`, `TAO/bin/tao_other_tests.lst`,
`ACE/tests/run_test.lst`) gate each test on configurations like `!ST !ACE_FOR_TAO !CORBA_E_MICRO`. A new test must
be added to the right list (and its `.mpc` to the enclosing workspace) or CI/scoreboards won't run it.
`run_test.pl` scripts use `PerlACE::TestTarget`, must not hang or need input, must clean up temp files, and must
exit non-zero on failure (`ACE/docs/run_test.txt`).

## Architecture

**ACE (`ACE/ace/`)** — layered: OS adaptation (`OS_NS_*.h`, `ACE_OS::` wrappers, `config-*.h` per platform,
feature macros in `config-macros.h`) → C++ wrapper facades (sockets, threads, sync, memory) → frameworks
(Reactor/Proactor event demultiplexing, Acceptor/Connector, Service Configurator, Streams, Task/Message_Queue,
CDR marshaling). `ACE/ace/` also contains sub-libraries (SSL, ETCL, Monitor_Control, QoS...). Other trees:
`ACEXML`, `Kokyu`, `protocols`, `netsvcs`, `apps/gperf` (used by TAO_IDL).

**TAO**
- `TAO/TAO_IDL/` — the IDL compiler (`tao_idl`): front end (`fe/`, `ast/`, `util/`) and C++ back end (`be/`,
  `be_include/`) using visitor classes to emit `*C.{h,cpp,inl}` (stubs) and `*S.{h,cpp}` (skeletons).
- `TAO/tao/` — the ORB core library (`libTAO`): ORB_Core, GIOP/IIOP transport & pluggable protocols, Transport/
  connection cache, invocation path, CDR. Many features are separate libraries in subdirectories loaded via the
  ACE Service Configurator: `PortableServer` (POA), `AnyTypeCode`, `DynamicAny`, `Messaging`, `IORTable`,
  `Valuetype`, `PI` (interceptors), `RTCORBA`, `CodecFactory`, `Strategies`, etc. Generated stubs for the
  ORB's own IDL (`*.pidl`) are checked in.
- `TAO/orbsvcs/` — CORBA services (Naming, Event, Notification, Trading, ImplRepo, LoadBalancing, AV, ...);
  `orbsvcs/orbsvcs/` holds the libraries, `orbsvcs/<Service>_Service` the executables, `orbsvcs/tests` tests.
- `TAO/tests/` — ORB regression tests; typical layout is `Test.idl`, `server.cpp`, `client.cpp`, an `.mpc` with an
  `*idl` custom-only project plus `taoserver`/`taoclient` projects, and `run_test.pl`.
- `TAO/utils`, `TAO/examples`, `TAO/DevGuideExamples`, `TAO/performance-tests`.

MPC base projects (`acelib`, `taolib`, `taoserver`, `taoclient`, `taoidldefaults`, ...) live in
`ACE/bin/MakeProjectCreator/config` and `TAO/MPC/config`; `.mpb` files there and in source trees encode library dependencies.

## Conventions

- Formatting: `.clang-format` (Mozilla-based, braces on their own lines, `SpaceBeforeParens: Always`, 123 cols).
  Match surrounding code; don't reformat untouched code.
- From `ACE/docs/ACE-guidelines.html`: in ACE use `ACE_TCHAR`/`ACE_TEXT()` for strings and `ACE_TMAIN` for
  `main`; TAO code does **not** use `ACE_TCHAR`/`ACE_TEXT` (CORBA strings are `char`). Use `ACE_OS::` wrappers
  instead of raw system calls for portability. Logging via `ACE_DEBUG`/`ACE_ERROR` (`TAOLIB_*` in TAO core).
- Each library has an export header (`*_export.h`, generated with `ACE/bin/generate_export_file.pl`); public
  classes need the export macro. `.inl` files are included from `.h` or `.cpp` depending on `__ACE_INLINE__`.
- User-visible changes go in `ACE/NEWS` / `TAO/NEWS` under the top "between X and Y" section.
